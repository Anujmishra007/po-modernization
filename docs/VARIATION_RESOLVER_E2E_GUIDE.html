What is V0 vs V2?

Critical Understanding

V0 and V2 are TWO DIFFERENT SQL SERVER DATABASES - NOT different versions of code!

Both are legacy systems. The new Java application replaces SP logic but still writes to V0 OR V2 database depending on which database the client uses.

VariationContext Model

public class VariationContext {
    private String version;           // "V0" or "V2"
    private String region;            // "ASIA-SG", "ASIA-KR", etc.
    private String client;            // "NIKE", "HM", "ZARA", etc.
    private String facility;          // "KR01", "SG02", etc.
    private String storerKey;         // Client identifier
    private boolean dualWriteEnabled; // Write to legacy?

    // Convenience methods
    public boolean isV0() { return "V0".equals(version); }
    public boolean isKorea() { return "ASIA-KR".equals(region); }
    public boolean isNike() { return "NIKE".equals(client); }
}
Field Type Purpose Example Values
version String Which database to write to V0 V2
region String Geographic region for plugins/config ASIA-KR ASIA-SG
client String Client/brand for plugins/config NIKE HM
facility String Warehouse facility code KR01, SG02
dualWriteEnabled boolean Write to both new and legacy true / false

How Version is Determined

Resolution Logic

storerKey facility version region client
NIKE_KR KR01 V2 ASIA-KR NIKE
NIKE_KR_V0 KR01 V0 ASIA-KR NIKE
V0_HM_SG SG02 V0 ASIA-SG HM
HM_SG SG02 V2 ASIA-SG HM
ZARA_TH TH01 V2 ASIA-TH ZARA
GENERIC IN01 V2 ASIA-IN STANDARD

Determination Rules

Version

V0 if:

  • storerKey starts with V0_
  • storerKey ends with _V0
  • Known V0 storer (from config)

Otherwise: V2 (default)

Region

From facility prefix:

  • KR → ASIA-KR
  • SG → ASIA-SG
  • TH → ASIA-TH
  • IN → ASIA-IN
  • MY → ASIA-MY
Client

From storerKey pattern:

  • Contains NIKE → NIKE
  • Contains HM → HM
  • Contains ZARA → ZARA
  • Contains ADIDAS → ADIDAS
  • Otherwise → STANDARD
